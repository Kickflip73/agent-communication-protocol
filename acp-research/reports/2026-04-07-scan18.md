## v2.74 候选特性

### 候选 A：`GET /trust/signals/capability-token` ⭐⭐⭐
- **来源**: #1716 @pshkv SINT PR #111 + pshkv/64R3N 讨论
- **内容**: 返回当前 relay capability token 声明（skill 边界 + 授权范围 + envelope constraints）
- **差异化**: A2A spec 尚无实现，ACP 可率先落地可查询 capability token 端点
- **实现成本**: 中（需定义 capability token schema + 新端点，可复用 trust signals 框架）

### 候选 B：`heartbeat_period_ms` in AgentCard ⭐⭐
- **来源**: #1667 heartbeat-based agents 讨论
- **内容**: AgentCard 声明 agent 心跳周期（ms），消费方据此判断 agent 是否"在线"
- **差异化**: 简单字段，填补 availability 感知空白
- **实现成本**: 低（CLI flag + AgentCard 字段 + capabilities 标志）

### 候选 C：`wtrmrk_sequence_root` in task metadata ⭐⭐
- **来源**: #1716 @64R3N 提议
- **内容**: Task 完成时在 metadata 中附加 WTRMRK 序列 Merkle 根
- **差异化**: 将行为历史与 task 绑定，增强不可否认性
- **实现成本**: 中（需构建简单 Merkle 树，写入 task metadata）

**推荐 v2.74 选择**: 候选 A — 与当前 trust signal 框架自然延伸，A2A #1716 今日热点，时效性最强
