## 6. v3.18 开发方向建议

> 背景：scan45 提出 4 个候选（P1-A RFC 9421, P1-B Liveness, P2-C OAuth 2.1, P3-D Availability）。本次扫描基于新数据调整优先级。

### 🔴 P1 候选 A — RFC 9421 HTTP 签名兼容层（升级确认）

**背景**: A2A #1829 从 123 → 139 评论（+16），社区关注度持续增长。A2A v1.1 规划（#1942）可能将此纳入核心。

**提案**:
- `POST /message:send` 请求支持 RFC 9421 HTTP Signature header
- AgentCard 新增 `auth_methods: [ed25519_per_message, http_signature_9421]`
- 与现有 Ed25519 per-message 签名并存，HTTP 签名为可选扩展
- `capabilities.http_signature_9421: true`

**价值**:
- 传输层安全增强，防止中间人篡改 HTTP 请求
- 与 A2A #1829 对齐，降低跨协议互操作门槛
- 保持 ACP 轻量，HTTP 签名为可选而非强制

**工作量估计**: 中等（约 1 开发轮）

---

### 🔴 P1 候选 B — Liveness Attestation 协议扩展（保持）

**背景**: A2A #1934 仍为 2 评论，新概念仍在早期。但 A2A v1.1 规划可能纳入。

**提案**:
- `POST /peers/<id>/liveness` — 发起活跃探测，返回 signed attestation
- Attestation 包含 `agent_id`, `timestamp`, `challenge_hash`, `response_signature`
- AgentCard 新增 `capabilities.liveness_attestation: true`
- 与 ACP v3.14 `skill_trust_score` 结合，活跃证明纳入信任评分

**价值**:
- 解决 Agent 网络中的 Sybil/ghost node 问题
- 与 A2A #1934 同步，抢占协议层 Liveness 标准
- 直接增强 ACP P2P 网络的可靠性

**工作量估计**: 中等（约 1 开发轮）

---

### 🟡 P2 候选 C — A2A v1.1 跟踪与互操作性增强

**背景**: #1942 TSC 提案提出 v1.1 scope alignment。A2A 正在规划下一版本，ACP 应提前准备互操作能力。

**提案**:
- 跟踪 A2A v1.1 提案（#1942, #1964, #1960）
- 实现 A2A v1.0 AgentCard 兼容解析器（读取 A2A AgentCard，适配 ACP 发现）
- 实现 A2A v1.0 Task 状态机兼容（5 种状态映射）
- 文档：ACP↔A2A 互操作指南

**价值**:
- 提前布局跨协议互操作，降低未来集成成本
- A2A 生态扩张（#1907 新增 partners），互操作需求增长
- 与 ACP 战略定位⑤（标准化）一致

**工作量估计**: 中等偏高（约 1.5 开发轮）

---

### 🟡 P2 候选 D — OAuth 2.1 / External IdP 接入层

**背景**: A2A #830 讨论 OAuth 2.1。MCP 生态也在引入 token-based 认证。

**提案**:
- `--accept-jwt-bearer` 模式：relay 接受标准 JWT Bearer Token（JWKS 验证）
- AgentCard 新增 `auth_methods: [ed25519, jwt_bearer]`

**价值**: 打通企业 IdP 集成通道，保持 Ed25519 默认

**工作量估计**: 中等（约 1 开发轮）
