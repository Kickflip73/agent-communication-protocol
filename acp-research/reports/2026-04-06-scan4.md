## 重大发现

### 🔴 #1712 — WTRMRK 信任等级 + TPM/SPIFFE Grade 分层（21💬，深度讨论爆发）

**参与者：** @aeoess（APS 设计者）、@VCOne-AI

**核心讨论演进：**

1. **Grade 0 冲突**：did:key = Grade 0 被指出有误——硬件 TPM 生成的 did:key 实际可信度远高于 SPIFFE SVID（RBAC 配置错误的集群）
2. **重分级提案**：从基于"方法"的分级 → 基于"证据"的分级（evidence-based regrade）
   - 关键抽象：`who vouched` 与 `how verifiable is this` 分离
   - SPIFFE 和 TPM 合并为 Grade 2 但携带不同 freshness 语义
3. **freshness 字段设计**：
   - SPIFFE SVID：隐式 freshness（轮转周期 minutes-hours）
   - TPM quote：快照型，`ttl: null` 但需要 relying party 自定义 "acceptable snapshot age" 策略

**ACP 战略影响：**
- 我们的 `effective_tier` 三因子公式（v2.58）的 `reputation_adj` 层正好对应这里的 evidence-based 调整
- v2.62 的 `wtrmrk_sequence_root` 查询本质上是提供 "attestation history" 作为证据，支持动态 regrade
- **ACP 已有的 `_compute_effective_tier()` 架构与此方向完全一致，无需大改**

### 🟡 #1716 — wtrmrk_sequence_root Merkle commitment（5💬，关键细节确认）

**最新评论 @64R3N（v2.62 目标的直接来源）：**

具体用例：T3 技能调用（如 `transfer_funds`）来自服务器从未见过的 Agent，当前 tier 公式：
```
effective_tier = max(T3_commit, delegation_depth_floor, reputation_adj)
```
没有 `attestation_history_adjustment` 时，只能靠 tier_rule（T3）和 depth_floor 决策。
`wtrmrk_sequence_root` 在 task metadata 中允许接收方查询外部注册表，得到历史调整分，让公式收敛到更精确的结论。

**@aeoess 补充：**
- WTRMRK Merkle commitment 过 agent action sequences 是 `attestation_history_adjustment` 的正确原语
- 直接查询（不需要 on-chain 验证 per interaction）保持 common path 快速
- 高 tier 技能（T3）可选择性要求此证据

**@MoltyCel 确认：**
- depth 只是实际证据的代理变量，attestation history adjustment 是更直接的信号
- live endpoint：`api.moltrust.ch/capability-token/validate`（WTRMRK 注册表原型）

## v2.62 战略确认

基于本轮扫描，v2.62 方向无需调整，优先级提升：

**目标：** `wtrmrk_sequence_root` 外部 reputation 查询
- `POST /tasks` body 可携带 `metadata.wtrmrk_sequence_root`（Merkle commitment，base64url）
- relay 查询 `api.moltrust.ch/capability-token/validate` 或 ACP 本地缓存
- 查询结果影响 `attestation_history_adjustment`（-1/0/+1），注入 `_compute_effective_tier()`
- fail-closed 降级：查询失败 → adj = 0（中性，不影响 tier），记录 warn log
- 新字段：`wtrmrk_verified`（bool/null）、`wtrmrk_grade`（int/null）、`attestation_history_adjustment`（-1/0/+1）

**新增考虑（来自 #1712）：**
- `wtrmrk_grade` 与 `freshness` 字段配合（snapshot vs rotation-based）
- 可在 `GET /skills/{id}/effective-tier` response 中暴露 `wtrmrk_adj` 分项，便于调试
