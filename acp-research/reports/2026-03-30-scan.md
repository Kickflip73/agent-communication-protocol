#### 🔥 IS #1672 — Proposal: Agent Identity Verification for Agent Cards
- **状态**: Open，102 评论（热度持续上升）
- **核心问题**: AgentCard 无协议级身份验证，仅依赖 TLS/OAuth（authorization ≠ identity）
- 最新提案：添加 `verifiedIdentity` 字段（ECDSA P-256 证书，中心化颁发机构）
- **🎯 ACP 对比**: ACP 使用 **Ed25519 + `did:acp:` 自主权 DID**，无需中心化颁发机构，设计更优

#### 🔥 IS #1667 — Heartbeat-based agents: availability metadata
- **状态**: Open，26 评论（2026-03-29 更新）
- **核心问题**: A2A 假设 agent 持续在线，不支持 cron/heartbeat 模式的调度 agent
- 最新讨论建议：AgentCard Extensions 机制添加 `scheduleType`, `cronExpression`, `nextActiveAt` 等字段
- **🎯 ACP 状态**: ✅ **已领先实现（v2.17.0，2026-03-30）**
  - `availability.schedule`（CRON 表达式）
  - `availability.timezone`（IANA 时区）
  - `GET /availability`：实时可用状态 + `next_active_at`
  - `POST /availability/heartbeat`：心跳戳记 + 自动重算下次激活时间
  - stdlib-only 实现，零外部依赖
  - 加上既有的 `offline_queue` flush-on-reconnect，完整覆盖 IS#1667 所描述的"offline-first"场景

#### IS #1628 — trust.signals[] extension: consolidated signal type specification
- **状态**: Open，18 评论（2026-03-29 更新）
- 4种信号类型：`onchain_credentials`, `onchain_activity`, `vouch_chain`, `behavioral`
- 所有信号类型统一使用 ECDSA/JWKS 验证模式（非 Ed25519）
- **🎯 ACP 状态**: ACP 已有 `trust.signals` 字段（v2.x），但使用 Ed25519 而非 ECDSA P-256

#### IS #1694 — Add 'limitations' field to AgentCard

## v2.18 候选特性分析

### 候选 A：trust.signals 算法对齐（Ed25519 → JWKS 兼容层）
- **背景**: IS#1628 用 ECDSA P-256 / JWKS，ACP 用 Ed25519
- **方向**: 提供 JWKS 验证适配器，使 ACP trust.signals 可验证来自第三方 ECDSA 提供商的信号
- **优先级**: P2（中期，生态互通价值高）

### 候选 B：data_handling_policy（GDPR 字段）
- **背景**: IS#1606 建议 AgentCard 声明数据处理政策
- **方向**: 可作为 Extensions 字段实现，`urn:acp:ext:data-handling/v1`
- **优先级**: P3（低，个人场景不迫切）

### 候选 C：NAT 穿透完整集成（v1.4 遗留项）
- **背景**: Level 2 TCP 打洞 `_connect_with_nat_traversal()` 仍未集成到主流程
- **方向**: 完成 Level 1/2/3 自动切换，验证双 NAT 场景成功率 ≥70%
- **优先级**: P0（核心差异化，Show HN 前必须完成）

### 候选 D：Show HN 发布准备
- 等待 NAT 穿透完成（v1.4 主流程集成）
- `docs/show-hn-draft.md` 已就绪
- 发布窗口：A2A 当前无大版本冲击，可择机发布
