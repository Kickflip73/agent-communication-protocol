### Issue #1716 — RFC: Authorization layer for A2A AgentSkill invocations
**更新时间：** 2026-04-05T00:50:45Z（今天凌晨）  
**状态：** Open

**与 ACP v2.49 的对应关系：**  
这正是我们在 v2.49 实现的特性的参考来源。A2A #1716 提议将 SINT Protocol 作为 A2A 技能授权互补层。

**SINT Protocol 设计要点（A2A 方案）：**
- 使用 **Ed25519 capability token** 编码 subject/resource/actions/tier/constraints/exp
- 通过 PolicyGateway 在 AgentSkill 执行前检查
- 需要独立的 token 发放基础设施
- 集成方式：在 A2A task handler 中提取 capability token 并验证

**ACP v2.49 与 SINT 的差异（我们的竞争优势）：**

| 维度 | SINT (A2A #1716 提案) | ACP v2.49 |
|------|----------------------|-----------|
| **授权凭证** | Ed25519 capability token（独立颁发） | 复用已有 trust.signals + trust_score（零额外基础设施） |
| **集成复杂度** | 需部署 PolicyGateway | 内置，无需额外服务 |
| **tier 定义** | T0_observe/T1_read/T2_act/T3_commit | T0/T1/T2/T3（语义一致） |
| **T3 要求** | capability token + human sign-off 流程 | trust_score ≥ 0.9 + verified_identity signal |
| **constraints 支持** | 参数级约束（max_amount, currency 等） | ❌ 暂不支持（v2.50 候选） |
| **跨组织** | 支持（token 可跨 org 颁发） | 依赖 vouch_chain / delegation_chain |

**可借鉴方向（v2.50 候选特性）：**
- `skill.constraints` 字段：参数级约束（max_amount、allowed_values 等），SINT 的强项
- T3 `human_confirmation` 流程：任务进入 `input_required` 状态等待人工确认后再执行

### Issue #1672 — Proposal: Agent Identity Verification for Agent Cards
**更新时间：** 2026-04-05T01:10:33Z  
**状态：** Open

**问题陈述：** A2A 当前没有标准化方式让接收方密码学验证 AgentCard 真实性，依赖 HTTPS/OAuth 做传输层信任。

**提案核心：**
- AgentCard 加入 `identity.proof` 字段（Ed25519 签名）
- 签名覆盖 AgentCard 关键字段（name/skills/capabilities/did）
- 接收方可离线验证 AgentCard 未被篡改

**ACP 现状（已领先）：**
- ACP v1.8：`card_sig` — Ed25519 AgentCard 自签名 ✅
- ACP v1.3：`did:acp:` / `did:key:` 稳定标识符 ✅
- ACP v1.9：`auto_card_verify` — 连接时自动验证 peer AgentCard ✅
- ACP v2.18：JWKS 兼容层 ✅

**评估：** ACP 在此议题上已全面领先，无需跟进。可在与 A2A 社区交流时作为 ACP 竞争优势宣传。
