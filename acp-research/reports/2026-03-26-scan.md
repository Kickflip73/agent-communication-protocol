# ACP 竞品情报扫描 — 2026-03-26

## A2A（Google / a2aproject）

### 版本动态
- **v1.0.0 正式发布（2026-03-12）** — 22k+ stars，这是 A2A 协议的首个稳定版本
- 上次扫描：v1.0.0-alpha（2026-03-19）；本次确认正式版已落地

### v1.0.0 关键变更（BREAKING）

| 变更 | 影响 |
|------|------|
| `extendedAgentCard` 移入 `AgentCapabilities` | AgentCard 结构调整 |
| OAuth 2.0 更新：移除 implicit/password，增加 Device Code / PKCE | 认证体系现代化 |
| URL 路径去掉 `/v1s/` 前缀 | API 端点 breaking change |
| `TaskPushNotificationConfig` 与 `PushNotificationConfig` 合并 | 推送通知 API 简化 |
| ProtoJSON 格式对齐 ADR-001（enum 格式标准化） | 序列化格式变化 |
| `canceled`（美式）替换 `cancelled`（英式）全局 | 细节拼写统一 |
| `final` 字段从 `TaskStatusUpdateEvent` 移除 | SSE 事件结构简化 |

### v1.0.0 新 Feature
- **`tasks/list` 方法**：支持过滤和分页（我们 v2.0 offline queue 场景可参考）
- gRPC 多租户支持：request 增加 `scope` 字段
- SDK 向后兼容性机制

### 开放 Issue（近期活跃）
- `Proposal: Agent Identity Verification for Agent Cards` — A2A 也在讨论 AgentCard 身份验证（与我们 v1.9 相同方向，值得持续跟踪）
- `[Bug]: GetTaskPushNotificationConfig returns sensitive security credentials` — 安全漏洞，敏感信息泄露 issue
- `[Bug]: CancelTaskRequest definition is missing`

### ACP vs A2A 差异化再确认
- A2A 做了大量 breaking changes 才到 v1.0，API 复杂度显著上升
- A2A Identity Verification 仍在 proposal 阶段；ACP v1.9 已实现 `GET /peer/verify`
- A2A 强 OAuth、gRPC、多租户 → 企业场景；ACP 坚守 curl 可接入、P2P → 个人/小团队

## 综合评估

### 值得 ACP 同步考虑的动向
1. **A2A `tasks/list` 分页**：未来 ACP 若引入任务管理，可参考其 `last_updated_after` + `page_token` 模式
2. **ANP `failed_msg_id`**：错误响应中回传 msg_id，有助于 offline queue 的 retry 追踪
3. **A2A AgentCard Identity Verification Proposal**：A2A 社区确认这是 2026 H1 的重点方向，ACP 已领先，可在 README/show-hn 中强调"已实现"

### 竞品焦虑指数：低
- A2A v1.0 breaking changes 多，生态迁移成本高
- ANP 活跃度放缓，专注 E2EE 垂直场景
- ACP 差异化清晰：P2P + 零配置 + curl 接入 + 单文件 Skill
