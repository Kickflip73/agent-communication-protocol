## 2. 深度分析

### 2.1 A2A #1716 — AgentSkill 授权层 capability token（关键）

**问题陈述（@原作者）：**
- A2A `SecurityRequirement` 只提供认证钩子，无 Skill 边界的**授权**机制
- 认证成功的 Agent 可调用 AgentCard 上的任意 Skill
- 不可逆操作（金融转账、物理控制、基础设施变更）缺乏分级审批流

**社区关键评论（@aeoess, @MoltyCel, @64R3N）：**
> "Authentication vs authorization at the skill boundary is the right decomposition, and SINT's capability token is the right primitive for the second layer."  
> — `@aeoess` (2026-04-05)

> "`wtrmrk_sequence_root` merkle commitment 是 attestation_history_adjustment 的正确原语——直接查询而非每次链上验证，保持普通路径快速。"  
> — `@aeoess` (2026-04-05)

**三层 Tier 公式（@64R3N 提案）：**
```
effective_tier = max(T3_commit, delegation_depth_penalty, history_adjustment)
```
- T3 Skill（如 `transfer_funds`）从未见过的 Agent：默认 `effective_tier = T3`
- 带有 `wtrmrk_sequence_root` 证明的 Agent：`attestation_history_adjustment` 降级到 T2

**与 ACP 的关联：**
- ACP v2.84 已实现 `capability_token` 签发（RFC-003 + RFC-004）
- `wtrmrk_sequence_root` 与 ACP `bilateral_ir` 的 merkle commitment 思路一致
- **差距**：ACP 当前无 Skill 级别的 tier 强制执行逻辑；relay 只做 transport，不做 Skill 授权

**建议行动（v2.96 候选）：**
- ACP spec 补充 `skill_auth` 章节：per-skill `required_tier` 声明 + capability token 验证接口
- relay `--skill-tier-enforcement` 模式：HTTP handler 对 `/task:create` 中的 skill 检查 token tier

### 2.2 A2A #1713 — OBO（On Behalf Of）跨组织首次交互

**背景：**
来自 `@pshkv`（SINT Protocol 作者）和 `@aeoess`（APS 作者）的独立验证，两个协议在跨组织场景的设计完全收敛：

> "SINT and APS arrived at the same cryptographic primitives independently: Ed25519 signatures, did:key identifiers, monotonic capability attenuation, no shared authority server."  
> — `@aeoess` (2026-04-04)

**跨验证结果（历史性）：**
> "@pshkv — ran the cross-verification test. **All 9 tests pass. Zero code changes on either side.**"  
> — `@pshkv` (2026-04-04), commit: pshkv/sint-protocol@f98e281

这意味着 **SINT + APS capability token 可互操作**，无需协议修改。

**OBO 填补的空白：**
- 跨组织 Agent 首次交互（无历史 IR）
- 无共享 AS（Authorization Server）
- 人类/法律实体委托链的 principal authority chain

**与 ACP RFC-004 的关联：**
- RFC-004（decentralized agent identity）已解决去中心化身份问题
- OBO 补充了"首次跨组织交互"的委托链场景，RFC-004 目前缺乏这一层
- **建议**：RFC-004 补充 `first_contact` 协议子章节，参考 OBO 的 principal_authority_chain 设计
