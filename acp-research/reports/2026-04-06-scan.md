## 关键发现

### 1. #1716 — SINT RFC 有了第一条实质性评论 🔥
**状态**: 1 comment (up from 0), @64R3N [2026-04-05]

**核心内容**：提出 **Effective Tier** 三因子公式：

```
effective_tier = max(
  tier_rule,                                      # 技能本身声明的 T0-T3
  delegation_depth_floor(depth),                  # principal_chain 深度惩罚
  attestation_history_adjustment(seq_len, recency) # 历史信誉调整
)
```

`attestation_history_adjustment` 返回值：
- `-1`：长期、近期有 WTRMRK 链上记录的 agent → 允许降低 tier 要求（信誉快速通道）
- `0`：中等历史，无调整
- `+1`：无外部记录的 unknown agent → 强制更高 tier 门槛

**ACP 影响**：
- 我们的 T0-T3 `authorization_tier` 是 tier_rule 层
- 我们的 `principal_chain[]` 深度已记录（v2.56），但未做 `depth_floor` 计算
- 缺少 `attestation_history` 层 → **v2.58 机会**：`effective_tier` 动态计算，而非静态赋值

### 2. #1713 — 首次联系信任栈 "历史缺口" 被明确
**状态**: 17 comments, 最新 @64R3N + @aeoess [2026-04-05]

**核心论点**：现有协议栈回答了"谁授权了这个 agent？"（OBO）、"允许做什么？"（APS）、"物理约束是什么？"（SINT），但没有回答**"这个 agent 历史上是谁？"**。

@aeoess 提出 `APS ActionReceipt.previousReceiptHash` 可作为链式历史证明：
- 200 条链式 receipt → 可验证的执行历史
- 需要 `attestation_anchor` 字段防止自签名伪造

**ACP 关联**：
- ACP v2.56 的 `principal_chain[]` 是 OBO 层的实现
- 尚未有 "agent 执行历史" 的概念
- 若 A2A 收敛到 `execution_receipt_chain`，ACP 可在 v2.59 跟进

### v2.58 目标更新
**原计划**：`effective_tier` 基于 principal_chain depth

**新精化（基于 #1716 comment）**：
```python
def compute_effective_tier(skill_tier, principal_chain, agent_reputation=None):
    depth_floor = min(len(principal_chain), 3)  # 最多 +3 级提升
    history_adj = _reputation_adjustment(agent_reputation)  # -1/0/+1
    return max(skill_tier, depth_floor, skill_tier + history_adj)
```

这样 v2.58 就不只是"深度惩罚"，而是完整的三因子 effective_tier——**比 A2A spec 本身还早收敛到正确设计**。
