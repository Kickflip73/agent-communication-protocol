## A2A 高优先级开放 Issues（新出现 / 近期活跃）

### 🆕 #1716 — RFC: Authorization at AgentSkill boundaries（2026-04-05 新开）
**核心问题**：A2A `SecurityRequirement` 只做身份认证，没有技能级别的授权边界。
任何已认证 agent 可调用任意 skill，包括 "irreversible" 类（转账、物理操控、基础设施变更）。

**提案方 SINT Protocol** 的补充方案：
- Ed25519 capability token，编码：`subject`/`resource`/`actions`/`tier`/`constraints`/`exp`
- 四层 tier：T0（观察）→ T1（读）→ T2（操作需审批）→ T3（不可逆需人签字）
- 参数级约束：`max_amount: 1000` / `currency: ["USD"]`

**ACP 当前状态**：
- ACP `QuerySkill() constraints`（v2.26）已支持 caller 端参数约束
- ACP `trust.signals[]`（v2.14）提供信任层
- ⚠️ **ACP 同样缺少 skill 级别的 authorization tier 概念**，这是一个真实的安全缺口
- **Action Item**: 考虑在 v2.49+ 引入 `skill.required_tier` 字段（T0-T3），与 trust.signals 联动

### 🆕 #1712 — WTRMRK 作为 A2A trust primitive（2026-04-04）
**核心内容**：WTRMRK（https://wtrmrk.io）是基于 Base (L2) 区块链的 agent 身份注册服务。
每个 agent 获得永久 UID，身份绑定到链上地址，解决"身份是 asserted 而非 proved"的问题。

**分析**：这是一个**中心化链上身份注册**方案，与 ACP 的差异化定位正相反：
- ACP：`did:acp:` 完全去中心化，无注册表，密钥对即身份
- WTRMRK：需要在 Base 网络注册，依赖链上交易，永久 UID 需第三方
- **结论**：ACP 差异化定位（offline-first, self-sovereign）更优。这类提案在 A2A 讨论区反复出现，说明社区对中心化身份方案的质疑在增加。

### 🆕 #1713 — OBO (On Behalf Of) 跨组织授权标准（2026-04-04）
**核心问题**：跨组织、跨境、无共享 AS 的 agent 交互场景：
1. **Principal authority chain** — calling agent 背后的人类/法律实体的授权链
2. **Cross-org first-contact auth** — 互不认识的两个 agent 首次交互，无法用 OAuth 联邦
3. **Tamper-evident evidence** — 可离线验证、可给监管机构看的任务完成证明
4. **Legal entity accountability** — agent 不是法人，operator（部署公司）承担责任

**与 ACP 的对比**：
| 问题 | OBO 方案 | ACP 现状 |
|------|----------|---------|
| 跨组织身份证明 | 自定义 authority chain 文档 | `delegation_chain`（v2.16）✅ 已实现 |
| First-contact auth | 文档+密钥锚点 | `did:acp:` + Ed25519 自签名 AgentCard ✅ |
| Tamper-evident record | 提案阶段 | `card_sig` + `trust.signals[]` ✅ |
| 法律责任链 | 核心诉求 | 超出 ACP 设计范围（intentional） |

**结论**：OBO 是企业级/监管合规场景的需求，ACP 定位个人/小团队，不需要 follow。但 `delegation_chain` 已先行实现了其部分技术诉求，可以在对比文档中提及。

## 本次扫描关键洞察

### 洞察 1：Skill 级别授权（SINT #1716）是真实缺口
A2A 和 ACP 都没有解决"谁有权调用哪个 skill"这个问题。
**ACP Action Item（v2.49）**: 引入 `skill.authorization_tier`（T0-T3）字段，与 `trust.signals` 联动：
- T0/T1（低风险）：自动执行
- T2（后果性）：调用前需 `trust.score >= threshold`
- T3（不可逆）：需外部 human-approval 信号

这不是照搬 SINT，而是用 ACP 已有基础（trust.signals + QuerySkill constraints）做轻量实现。
