## 🔴 重点动态

### 1. A2A v1.0.1 发布准备中（PR #1706）
- v1.0.0 于 2026-03-12 发布，v1.0.1 PR 今日开放
- **内容：纯维护性修复**（pin check-spelling action、OSPO action 路径修正）
- 无协议层面变更，ACP 无需跟进

### 2. 自定义协议绑定文档合并（PR #1619 → merged 2026-04-07）
- 新增 `docs/topics/custom-protocol-bindings.md`
- 定义 Custom Protocol Binding（CPB）与 Extension 的概念边界：
  - **CPB**：替换 HTTP/JSON 传输层（如 gRPC、SLIM、MQTT）
  - **Extension**：在现有传输层上扩展功能
- 新增 spec §5.8：URI-based binding identification（SHOULD requirement）
- Agent Card 中声明方式标准化

> **ACP 影响**：ACP 定位为"轻量 P2P 零依赖"，本次变更强化了 A2A 对多传输协议的开放性，与 ACP 的 NAT 三级降级机制理念相符。未来可在 ACP spec 中增加 CPB 声明字段（低优先级）。

### 3. 新议题：experimental-cpb-slimrpc（Issue #1723）
- 提议在 a2aproject 下创建 `experimental-cpb-slimrpc` 仓库
- SLIMRPC = A2A over [SLIM](https://github.com/agntcy/slim)（Secure Low-Latency Interactive Messaging，Agntcy 开发）
- Agent 寻址方式：三元组层级名称（`namespace/group/name`），不走传统 HTTP URL
- 还在提议阶段，尚未批准

> **ACP 参考价值**：SLIM 的"非 HTTP URL 寻址"与 ACP 的 `acp://relay/<token>` 链接格式思路相近。值得持续观察其命名方案。

### 4. Agent Identity Verification（Issue #1672，持续活跃）
- 核心问题：接收方无法加密验证 Agent Card 的真实性
- 当前 A2A 仅依赖传输层信任（HTTPS/OAuth），覆盖 authorization 但非 identity
- 提案方向：Ed25519 签名 + DID 锚定 + JWK thumbprint

> **ACP 影响**：ACP 已有 `card_signature` + `delegation_chain` 实现，属于该方向的先行参考实现。无需跟进，可在 PR 中引用 ACP 方案作为参考。

### 5. Task Lifecycle Evidence Sample（Issue #1721）
- 外部消费者分享 A2A 任务生命周期证据样本
- 聚焦：`task.requested` + `task.updated` 两个事件
- 关键 artifact：success / failure / malformed 三类
- 仓库：https://github.com/Rul1an/assay/tree/main/examples/a2a-task-evidence

> **ACP 影响**：ACP Task 状态机（v0.5 里程碑，5 种状态）覆盖上述场景。可参考 malformed artifact 作为测试场景 F 的补充用例。
