## 对 ACP 的影响评估

### 1. A2A 的影响

**差异化机会：**
- A2A v1.0 已冻结，GA 后以文档和生态建设为主。**ACP 仍在协议层有创新空间。**
- A2A 的 Task 状态机移除了 `final` 字段，显示其对"终态感知"的态度是简化而非精细化。**ACP 若引入更完整的 Task 状态机（含幂等 ID、版本号、终态语义），是明显差异化点。**
- A2A 的 `non-complex IDs` 设计限制了请求级幂等性扩展空间。**ACP 的幂等设计可以更丰富。**
- A2A 正在开放 custom protocol bindings，但仍以 HTTP+gRPC 为核心。**ACP 若原生支持 P2P/WebRTC 传输，差异化更明显。**

**值得借鉴：**
- oauth2 modernization（device code + PKCE）是安全最佳实践，ACP 应跟进。
- AgentCard 中的 Governance metadata（正在讨论中）是有价值的方向。
- 能力令牌（capability token）用于 Skill 级别授权，ACP 可参考。

### 2. ANP 的影响

**安全认证层高度重叠：**
- ANP 密集在 `DataIntegrityProof`、`origin_proof`、`sender Proof scheme`、`OPK`（一次性预密钥）等方向发力，与密码学级身份证明深度绑定。这是 ANP 的核心差异化。
- **ACP 若不计划支持这类密码学证明，应明确"不做"的边界；若计划做，应尽快明确方案以免被 ANP 抢先。**

**群组协议与状态机：**
- ANP 在本轮大幅扩展了群组 E2EE 和群治理状态机（`group governance state machine`），包括 group.remove 终态语义、治理通知等。
- `expected_group_state_version` 的移除值得关注：这意味着 ANP 从版本向量同步转向了其他状态一致性方案。
- **如果 ACP 涉及多方协同场景，需要考虑群状态一致性的方案设计。**

**P2P 直连 E2EE：**
- ANP 持续更新 `direct e2ee`（直连端到端加密），说明其 P2P 能力是主干功能。
- **ACP 的 P2P 连接方向与 ANP 存在直接竞争，需要明确技术路线。**

## 结论

1. **A2A 已 GA（v1.0.0），协议层冻结**，后续以生态拓展为主。ACP 在协议创新窗口仍然开放，但需加快节奏。

2. **ANP 处于高速迭代阶段**（本轮 50 commits），核心方向是密码学安全认证（DataIntegrityProof、origin_proof、sender Proof）和群组 E2EE，与 ACP 在安全认证领域存在直接竞争。

3. **安全认证是本轮最热的主题**：A2A 社区在讨论 capability token、bilateral signed records、cross-org accountability；ANP 在实现 DataIntegrityProof 和 origin_proof。**ACP 的认证方案设计已刻不容缓。**

4. **Task 状态机差异化机会**：A2A 简化了状态机（移除 final），ANP 专注于群组状态机。ACP 可以在单任务状态机的幂等性和可追溯性上建立差异化优势。

5. **协议分层是共同趋势**：A2A 分离 application protocol 和 transport binding；ANP 有 Handle/Federation 层。**ACP 的协议分层设计应尽早明确，避免后期架构债。**
