## 详细分析

### #1712 — WTRMRK Grade 模型演进（+2 💬）

**VCOne-AI → @aeoess 讨论焦点：Grade 2 内部分层**

当前收敛方向：
- **Grade 0**：裸密钥，无外部证明
- **Grade 1**：第三方背书（CA/DID registry）
- **Grade 2**：基础设施绑定（SPIFFE/TPM/HSM） ← 新问题出现
- **Grade 3**：法人绑定（政府/监管级别）

**新发现：Grade 2 内部 freshness 差异**

| Grade 2 类型 | freshness | 问题 |
|-------------|-----------|------|
| SPIFFE SVID | 隐含（SVID 轮换，分钟-小时） | 消费方可依赖 SVID TTL |
| TPM quote | `ttl: null`（快照型） | 消费方不知如何判断快照是否过期 |

**@aeoess 提出的 `freshness` 字段结构：**
```json
{
  "grade": 2,
  "method": "tpm-attestation",
  "freshness": {
    "type": "snapshot",
    "issued_at": "2026-04-05T10:00:00Z",
    "ttl": null,
    "policy_hint": "acceptable_age_max_hours"
  }
}
```

**@VCOne-AI 反驳**：`ttl: null` 把过期判断推给每个消费方，缺乏标准化 → 需要 `max_age` 字段或 stale flag。

**ACP v2.64 机会：**
- ACP `_build_governance_metadata()` 当前 trust_score 是静态数字
- 可以在 governance_metadata 中加入 `grade_evidence` + `grade_freshness` 字段
- 对接 WTRMRK 时携带 `method`（did:key/TPM/...）和 `freshness.issued_at`

### #1717 — APS `passportToAgentCard()` 生产实现（**+1 NEW 💬**）

**@aeoess 揭示了关键生产细节：**

1. **动态 governance endpoint**（非静态 Agent Card）
   ```typescript
   passportToAgentCard(passport, { url, skills, securitySchemes })
   // card.extensions['agent-passport'].serviceEndpoint
   // => "https://gateway.aeoess.com/api/v1/public/trust/{agentId}"
   ```
   接收方调用 endpoint，得到：grade(0-3)、active_constraints、delegation_chain_hash、behavioral_continuity

2. **static trust_score 的根本问题**：
   - 静态 trust_score 会过期
   - APS 方案：Agent Card 携带 serviceEndpoint，接收方**按需查询**最新 trust profile

3. **ACP v2.60 `GET /governance-metadata` 已经是这个方向**！
   - 我们的实现：接收方可以 GET `/governance-metadata` 获取 live 数据（peer_count/task_count/runtime counters 都是实时计算）
   - APS 的模式是 Agent Card 里嵌 endpoint URL，而不是直接在 AgentCard 中存 static score
   - **机会**：ACP v2.64 可以在 AgentCard 的 governance_metadata 中加入 `live_endpoint: /governance-metadata`，与 APS serviceEndpoint 模式对齐
