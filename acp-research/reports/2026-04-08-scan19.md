### 🆕 #1723 — SLIMRPC Custom Protocol Binding Proposal (2026-04-07 by @Tehsmash)
**最新动态**: 提议在 `a2aproject` 下建立 `experimental-cpb-slimrpc` 仓库，为 A2A 提供基于 SLIM（Secure Low-Latency Interactive Messaging）的新协议绑定。
- Agent 通过 `namespace/group/name` 三段层级名称寻址，而非 URL+port
- 认证由 SLIM 网络层管理，无需 HTTP headers / TLS 应用层配置
- 适合 NAT 场景、Edge 环境、多 Agent Mesh 部署
- 已有 Go + Python 双语言参考实现，支持 A2A v0.3.0

**ACP 关联**: ACP 当前绑定为 HTTP REST + SSE，SLIMRPC 的名称寻址模型与 ACP Handle 机制存在对应点（ANP `add handle feature` 2026-03-05 的方向一致）。

## v2.81 候选特性分析

### 候选 A：`POST /tasks/{id}/evidence` — 任务生命周期外部证据锚点 ⭐⭐⭐
- **来源**: A2A #1721 (@Rul1an, 2026-04-07) — Assay 框架探索"最小稳定证据接缝"
- **内容**: 支持外部 evidence consumer 提交 task 生命周期证据（requested/updated/completed artifact）
- **差异化**: A2A 仅讨论接缝设计，ACP 可率先定义可写证据端点，完整任务→证据链闭环
- **实现成本**: 中（复用现有 task 生命周期结构 + 新增 evidence 子资源）
- **与 ACP 已有设计的关联**: 与 bilateral IR log、trust signals 框架自然延伸

### 候选 B：`GET /protocol-binding/compatibility` — 协议绑定兼容性矩阵 ⭐⭐
- **来源**: A2A #1723 SLIMRPC + v2.79.0 protocol_binding 已落地
- **内容**: 返回当前 ACP relay 支持的协议绑定列表及互通能力矩阵（HTTP/gRPC/SLIM/future）
- **差异化**: v2.79.0 已有 `GET /protocol-binding`，可自然扩展为兼容性声明
- **实现成本**: 低（扩展现有端点响应 schema）

### 候选 C：`PUT /agent-card/availability` — 完整调度元数据写入 ⭐⭐
- **来源**: A2A #1667 heartbeat agents 讨论（scheduleType/cronExpression/nextActiveAt/taskLatencyMaxSeconds）
- **内容**: 支持通过 REST 更新 AgentCard 的完整调度/可用性元数据，而非仅 heartbeat_period_ms
- **差异化**: v2.80.0 实现 heartbeat_period_ms，本候选为可用性语义完整化
- **实现成本**: 中（扩展 AgentCard schema + 写入端点）

### 候选 D：`GET /tasks/{id}/lifecycle-events` — 任务生命周期事件流 ⭐⭐
- **来源**: A2A #1721 task evidence 讨论 + ANP server_seq 排序机制
- **内容**: 返回 task 的完整生命周期事件序列（requested/updated/completed），可选 SSE 流式推送
- **差异化**: 与 ANP E2EE IM 的 server_seq 排序机制对齐，为跨协议证据验证奠基
- **实现成本**: 中（SSE 流已有，需扩展 task 事件存储）
