### 热门 Issues（ACP 关联度高）

#### 🔴 Issue #1672 — Agent Identity Verification（403 评论，持续高热）
- A2A 仍无协议级身份验证，依赖 transport-layer (HTTPS/OAuth)
- **ACP 优势**：我们在 v1.3 已实现完整 Ed25519 + DID，v2.85 升级为默认开启
- A2A 社区在讨论，我们已落地 → **继续宣传这个差异化优势**

#### 🟡 Issue #1716 — Authorization layer for AgentSkill invocations
- 提案：给 Skill 调用加权限控制层（capability-based access）
- 对 ACP 影响：我们的 Skill 模型更简单，可作为轻量对比案例

#### 🟡 Issue #1717 — Governance metadata in AgentCards
- 提案：AgentCard 加入治理元数据（owner、policy、compliance）
- 对 ACP 影响：可考虑在 v2.9x 的 AgentCard 中加 `governance` 字段（低优先级）

#### 🟡 Issue #1723 — SLIMRPC custom protocol binding 提案
- 基于 SLIM (Secure Low-Latency Interactive Messaging) 的 A2A 绑定
- SLIM 是 Agntcy 的开源低延迟消息网络
- 对 ACP 影响：A2A 在走多协议绑定路线；ACP 专注 WebSocket P2P，定位互补

## 战略评估

### ACP vs A2A 当前格局
| 维度 | ACP v2.85 | A2A v1.0.1 |
|------|-----------|------------|
| 身份认证 | ✅ Ed25519+DID，默认开启 | ❌ 仍无（讨论中） |
| 协议复杂度 | 🟢 极简，单文件 | 🔴 企业级，学习曲线陡 |
| 运行环境 | 🟢 零依赖，curl 可接入 | 🔴 需要 agent framework |
| 协议绑定 | 🟡 WebSocket（主）+ HTTP/SSE | 🟢 多绑定（HTTP、SLIMRPC…） |
| 社区规模 | 🔴 早期 | 🟢 23k stars |

### 本周建议（v2.86 Show HN 冲刺）
1. **身份认证是最强卖点**：A2A 社区 403 人讨论还没做，我们已做好 → Show HN 重点突出
2. **"curl 可接入"差异化**：强调极简接入，对比 A2A 的 framework 依赖
3. **Custom Protocol Bindings 方向观察**：A2A 在开放协议绑定扩展，未来可考虑 ACP 提供 A2A 兼容 binding（v3.x 远期规划）
