### #1718 [NEW 0💬] — Bilateral Signed Interaction Records as Trust Primitive
**作者**：unknown  
**创建**：2026-04-05T21:17（UTC）

#### 核心洞察
提出「双边签名交互记录」作为 A2A 信任体系的**统一原语**，一个 JSON 对象解决身份+信任+审计+委托+Sybil 防御所有问题。

**数据结构**：
```json
{
  "type": "interaction",
  "public_key_a": "ed25519:abc...",
  "public_key_b": "ed25519:def...",
  "sequence_number_a": 42,
  "sequence_number_b": 17,
  "previous_hash_a": "sha256:...",
  "previous_hash_b": "sha256:...",
  "timestamp": 1743897600000,
  "transaction": {
    "task_id": "a2a:task/uuid",
    "action": "task_completed",
    "quality": 0.87,
    "skill": "code_review"
  },
  "signature_a": "ed25519:...",
  "signature_b": "ed25519:..."
}
```

**解决的问题矩阵**：
| 问题 | 解法 |
|------|------|
| Identity | Ed25519 keypair，无注册表，离线可用 |
| Trust scores | 从交互记录图计算（NetFlow / MeritRank），图拓扑自动抓 Sybil 环 |
| Audit trails | 记录本身就是审计，双方持有相同拷贝，EU AI Act Article 12 就绪 |
| Delegation | 委托记录 = 有 TTL + depth 限制的 scoped 交互记录 |
| Sybil detection | 聚类分析：fake agents 形成孤立群集 |
| Negative reputation | 双方共签，无法伪造负面评价，无法否认糟糕结果 |

#### ACP 关联评估

**高度相关**！ACP 已有：
- `trust.signals[]` (v2.14)
- `principal_chain[]` (v2.56)
- `capability_token` Ed25519 (v2.57)
- `effective_tier` 三因子 (v2.58)

**缺失的部分**：「双边签名」——目前 ACP 的信任证据都是单方声明。
#1718 的 `signature_a` + `signature_b` 要求**服务方也签名**，形成真正不可否认的双边记录。

**v2.59+ 机会**：`POST /tasks` 完成时，relay 可选择生成双边交互记录（`interaction_record`），
要求调用方预签名 + relay 签名，返回给调用方保存。这比 A2A spec 更早实现。

## 🎯 ACP 战略建议

### 立即可行（v2.59）
**双边交互记录（轻量版）**：
- `POST /tasks` 完成时生成 `interaction_record`（可选，`record=true` 参数）
