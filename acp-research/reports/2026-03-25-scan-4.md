## 🔴 高价值情报：Cancel Task 语义争议（A2A #1680 + #1684）

### A2A Issue #1680：Cancel Task 不能立即完成时如何响应？

**问题核心：**
当 Cancel Task 被调用，但取消操作需要时间（回滚等耗时操作），应该：
- Method 1：同步返回 Task 对象，状态为 `WORKING`（"正在取消中"）
- Method 2：返回新状态 `CANCELING`（中间状态）

**社区争议点：** A2A spec 目前无明确规定，导致实现分歧。

### A2A Issue #1684：CancelTaskRequest 定义缺失

**问题核心：**
1. spec 中 `CancelTaskRequest` 的定义缺失
2. Agent 收到取消请求后，SSE 长连接应该：先发 `TASK_STATE_CANCELED` 事件再关闭？还是直接断连？
3. 取消无法立即完成时，cancel API 返回什么状态？

## 🟢 ACP 当前实现优势（对比 A2A 痛点）

我们在 v1.5.2（spec §10）中已经解决了这两个问题：

| 问题 | A2A 状态 | ACP 实现 |
|------|---------|---------|
| Cancel 不能立即完成 | 无规定，社区争议 | 同步完成（spec §10 明确要求） |
| 取消终态任务 | 不清楚 | 409 ERR_TASK_NOT_CANCELABLE，幂等 |
| CancelTaskRequest 定义 | 缺失 | `{task_id}:cancel` POST，空 body |
| SSE + cancel 交互 | 模糊 | cancel 直接终止，SSE 关闭 |

**结论：ACP cancel 语义比 A2A 更清晰，可在 README/spec 中强调这一差异化优势。**

## 🟡 A2A Issue #1683：SSE contextId 缺失（spec 内部矛盾）
