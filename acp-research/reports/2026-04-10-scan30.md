## 2. 深度分析

### 2.1 A2A #1667 — Heartbeat-based agents（与 ACP 高度相关）

**问题陈述：**
A2A spec 假设 Agent 是持续服务的 live endpoint，但大量真实部署是"心跳型 Agent"：
- 按 cron 调度（如每 4 小时）
- 无持久化服务器进程
- 醒来处理任务，完成后休眠

**当前 spec 缺口：**
1. `AgentCard` 无法声明 Agent 的可用窗口（availability window）
2. 无 offline-first task queuing 机制
3. 发现时 Agent 可能处于离线状态

**社区建议方向（33 评论）：**
- `AgentCard` 扩展字段：`availability: { schedule: "0 */4 * * *", next_online_at: "..." }`
- Task 投递支持 "queue for next wake" 语义
- Relay 代为接收 + 缓冲消息，Agent 唤醒时 pull

**与 ACP 的关联（关键）：**
- ACP 的 relay 架构天然支持离线接收：Agent 断线时 relay 可缓冲消息
- ACP `acp_relay.py` 本身就是"心跳型"（作为本地守护进程随 Agent 启动）
- **差距**：ACP 当前无 `availability` 元数据声明；relay 无消息持久化（连接断开消息丢失）
- **机会**：ACP 可比 A2A 更早实现这个场景，强化"个人/小团队"定位

**建议行动（v2.97 候选）：**
- relay 增加 `--persist-queue` 模式：peer 离线时消息写入本地 SQLite，重连后推送
- AgentCard 扩展 `schedule` 字段（可选）
- 在 Show HN 中可用此 issue 作为佐证："A2A 社区正在讨论的问题，ACP 已有方向"

### 2.2 A2A #1718 — Bilateral Signed Interaction Records

**核心思想：**
> "一个 JSON 对象，双方签名，记录两个 Agent 之间发生的事情。信任、声誉、审计日志、Sybil 防护和委托证据全部从这些记录的图谱中派生。"

**提案的 5 个统一目标：**
1. Trust（信任评分来自历史记录图）
2. Reputation（声誉 = 不可篡改的签名记录）
3. Audit trails（每次交互留痕）
4. Sybil resistance（新 Agent 无历史 → 初始低信任）
5. Delegation（委托链通过链式签名表达）

**与 ACP bilateral_ir 的对比：**
- ACP 在 v2.84 已实现 `bilateral_ir`（互签交互记录）
- A2A #1718 的设计与 ACP bilateral_ir 几乎同构：双方签名 + JSON + 图结构
- **ACP 领先** A2A 至少 2-3 个月实现了这一 primitive

**建议行动：**
- 在 A2A #1718 评论区发布 ACP bilateral_ir 实现参考（已有真实代码）
- 这是 ACP 在 Show HN 前建立社区曝光的绝佳机会
