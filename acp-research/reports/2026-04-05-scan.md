## v2.52 候选特性评估

### 候选 A：`GET /tasks/{id}/audit-log` — 任务审计日志端点 ⭐⭐⭐⭐
- **背景**：v2.49-v2.51 引入了 tier/param/confirm 三层防护，但没有审计记录
- **价值**：合规场景下 T3 操作必须可追溯（谁请求 → 谁确认 → 何时执行）
- **设计**：每个 task 维护 `audit_log[]`，记录关键事件（created/tier_checked/param_validated/confirmation_requested/confirmed/rejected/submitted/completed）
- **ACP 差异化**：A2A #1716 只提 token enforcement，无审计设计；我们可首创

### 候选 B：`skill.deprecation_notice` — Skill 废弃通知字段 ⭐⭐⭐
- **背景**：Agent 需要优雅地废弃旧 skill，给调用方迁移窗口
- **设计**：`{"deprecated": true, "deprecated_since": "2026-04-01", "sunset_at": "2026-05-01", "replacement_skill": "transfer_v2", "message": "..."}`
- **行为**：调用废弃 skill 时，POST /tasks 返回 200 但响应附带 `deprecation_warning` 字段
- **ACP 差异化**：A2A 无此字段

### 候选 C：`POST /tasks/{id}:cancel` — 任务取消端点 ⭐⭐⭐
- **背景**：tasks 目前只能走 :confirm/:reject，缺少对进行中任务的取消
- **设计**：支持 working/submitted 状态任务的取消，进入新状态 `cancelled`
- **注意**：需确认与现有状态机的兼容性

### 候选 D：`AgentCard signature` 验证端点 ⭐⭐⭐（跟随 A2A 热点）
- **背景**：A2A #1672/#1712 热议，身份验证需求真实
- **设计**：`POST /verify-card` 接受 AgentCard JSON + 签名，返回验证结果
- **ACP 现状**：v2.18 JWKS 已有基础，可在此之上扩展
- **风险**：引入密码学依赖较重

## 推荐 v2.52 方向

**优先：候选 A（audit-log）**
- 与 v2.49-v2.51 三层防护自然延伸
- 合规价值高，实现复杂度中等
- A2A 无对应设计，差异化明确

**次选：候选 B（skill deprecation）**
- 实现简单（纯数据字段 + 响应注入），可与 v2.52 打包

## 结论

- A2A 本周主要热点：身份验证（3 个相关 issue 同日活跃）；我们已有 JWKS 基础
- ANP 本月停滞，无需追踪
- v2.52 建议：**任务审计日志** (`audit_log[]`) + 可选附带 **skill deprecation_notice**
