## A2A 本周高价值动态

### 🔴 重点 — #1716 [2026-04-05 今日新开] RFC: Authorization layer for A2A AgentSkill invocations
**标题：** Authorization layer for A2A AgentSkill invocations — capability token enforcement at skill boundaries  
**热度：** 0 评论（刚开）  
**核心问题：**
- A2A `SecurityRequirement` 只管认证，不管**授权**
- 调用方通过认证后可以调用 AgentCard 里**任何** skill，没有任何约束
- 高风险 skill（金融转账、物理执行）没有分级审批流

**提案：** SINT Protocol 作为 skill 调用边界的 capability-token 层（Ed25519 token，encode `sub/aud/iat/exp/skills[]`）

**ACP 对比评估：**
| 特性 | A2A + SINT（提案中） | ACP（已实现） |
|------|-------------------|----|
| skill 级别调用授权 | RFC 阶段，0 合并 | ✅ v2.49 T1-T3 authorization_tier |
| 参数级约束 | 未提及 | ✅ v2.50 param_constraints |
| T3 人工确认 | 未提及 | ✅ v2.51 human_confirmation |
| 调用频率限制 | 未提及 | ✅ v2.53 skill.rate_limit |

**结论：** ACP 在这个方向已完全领先 18 个版本。可在 GitHub Issue 下评论，展示差异化。

### 🟡 重点 — #1713 [2026-04-04] Cross-org, no shared AS: OBO accountability layer
**热度：** 15 评论  
**核心问题：**
- 两个从未交互的 agent，没有共享 AS，A2A 的 OAuth 委托无法工作
- 缺乏：主体权威链（谁委派了调用方 agent？背后是哪个法人？）
- OBO（On Behalf Of）是一个解决跨组织、跨境 agent 事务的草案标准

**ACP 对比评估：**
- ACP v2.27 的 `vouch_chain` 提供了类似的主体链记录
- ACP 的 `trust.signals` + `did:acp:` 覆盖了零先验关系的身份验证
- 差距：ACP 目前无法表达"法律实体"层级的委托链（OBO 的核心是合规可审计）
- **潜在借鉴：** 在 AgentCard `trust` 字段添加 `principal_chain[]`（法人层级委托信息）

### 🟡 重点 — #1712 [2026-04-03] WTRMRK as a trust primitive for A2A agents
**热度：** 10 评论  
**核心内容：**
- WTRMRK = 基于 Base 链的 agent 身份层（RSA 签名 + 链上证明 + x402 支付身份）
- 提案：A2A 可选集成 WTRMRK 作为第三方身份验证

**ACP 对比评估：**
- ACP v1.8 的 Ed25519 自签名 AgentCard 已解决"无需第三方"的身份验证
- ACP v2.54 `POST /verify-card` 提供了独立验证任意 AgentCard 的完整工具链
- 区别：WTRMRK 需要区块链注册（中心化 + 收费），ACP 是零中心节点
- **ACP 优势定位：** "P2P Zero-CA 身份验证，无需区块链，无需注册服务"
