#### #1716 — RFC: capability token 授权执行（updated 2026-04-10）
- **状态：** open，24 条评论，最新更新 2026-04-10T16:34

- **最新讨论进展：**

- **趋势：** 讨论高质量，已有多方实现经验支撑；缺 A2A 核心团队的 official response，短期不太可能合并进规范

#### #1717 — Governance metadata in A2A Agent Cards（updated 2026-04-11）
- **状态：** open，**22 条评论**（最活跃 issue）
- **核心提案（microsoft/agent-governance-toolkit）：** 扩展 AgentCard 携带：

  - `policyCompliance`：所遵循的治理标准（ATF/OWASP 等）
  - `auditTrailReference`：防篡改审计链端点
- **最新讨论进展（2026-04-08）：**

- **趋势：** 具体实现层面收敛良好；live audit endpoint vs 静态声明 的争议是最后一个分歧点

## ACP v3.4 方向评估

### 从上游趋势看 v3.4 的核心命题

基于 A2A + ANP 的最新动态，v3.4 应聚焦以下三个方向：

#### 方向 A：AgentCard 信任与治理扩展（优先级：★★★★★）

**对应上游：** A2A #1717（Governance metadata，22 条评论，最活跃）+ #1716（capability token，24 条评论）

**推荐设计：**
```
AgentCard.governance:
  trustScore: float          # 归一化合规分值 [0.0, 1.0]
  capabilityManifest: []     # 机器可读许可能力列表
  policyCompliance: []       # ["ATF", "OWASP-ASVS-4", ...]
  auditEndpoint: url         # live REST 审计链端点（非静态）
  credentialLifecycle:
    maxSessionDurationSeconds: int
    revocationEndpoint: url
    credentialTTLSeconds: int
```

**理由：** #1717 的讨论已完成 CredentialLifecyclePolicy 具体实现，ACP 可以作为 early adopter 直接落地

#### 方向 B：Skill 级 Capability Token（优先级：★★★★☆）

**对应上游：** A2A #1716

**推荐设计：**
```
AgentSkill.authorization:
  requiredCapabilities: []   # 调用此 skill 所需的 capability token 范围
  tokenEndpoint: url         # capability token 获取端点
  delegationPolicy: "monotonic-narrowing" | "fixed"
```

**理由：** 当前 ACP v3.3 的认证层（OAuth/mTLS）不足以做授权隔离；#1716 的 `monotonic-narrowing` 委托模型成熟，可直接引用

#### 方向 C：ANP DataIntegrityProof 集成（优先级：★★★☆☆）

**对应上游：** ANP `DataIntegrityProof` + `origin_proof` 最新更新

**推荐设计：** 在 ACP 消息层引入可选的 `dataIntegrityProof` 字段，支持：
- `ecdsa-sd-2023`（选择性披露，隐私保护场景）
- `eddsa-rdfc-2022`（高效签名，性能优先场景）

**理由：** ANP 已经在 04-10 做了深度更新，ACP 若引用 W3C DIP v1.1 标准可与 ANP 形成兼容性，降低跨协议互通成本
