## 二、关键 Issue 动态

### #2028 — Actor-chain extension: on-behalf-of delegation（新）
- **作者**: kennethsinder
- **状态**: Open, 0 评论
- **日期**: 2026-07-03
- **内容**: 提议在 A2A 消息中增加 `actorChain` 字段，用于在多 Agent 委托链中传递"谁在代表谁操作"的身份信息。
- **设计**: 基于 RFC 8693 `act` claims，与 OAuth 工作组 ID-JAG/WIMSE 草案对齐。
- **与 ACP 关联**: 与 ACP 的 P2P 无中心设计有差异 — A2A 倾向携带委托链元数据，ACP 更倾向轻量直连。但 `actorChain` 的审计需求值得关注。

### #2026 — Trace Context Extension for Cross-Protocol Audit Chains（新）
- **作者**: kuangmi-bit
- **状态**: Open, 0 评论
- **日期**: 2026-07-03
- **内容**: 跨协议（A2A ↔ MCP）追踪上下文扩展，使用 W3C Trace Context 标准，定义 A2A→MCP 双向桥接行为。
- **设计**: 利用 A2A extension 机制，零新协议，嵌入 `metadata`。
- **参考实现**: Go 版本（19 tests）+ MCP companion。
- **与 ACP 关联**: 审计追踪是 Agent 通信的重要维度。ACP 目前无 trace 概念，未来如需支持多跳调试可参考此设计。

## 三、A2A v1.1 路线图推断

基于 #1942 合并计划，v1.1 可能聚焦 5 大方向：
1. **Stream resumption** — 流式会话恢复
2. **Idempotency** — 消息幂等（ACP 已实现，v3.16）
3. **Push-config** — 推送配置
4. **Skill selection** — 技能选择（ACP v3.19 skill_id routing 直接对齐）
5. **Auth discovery** — 认证发现

## 六、扫描结论

A2A 社区在 v1.1 规划期有 3 个值得 ACP 持续跟进的趋势：
1. **委托链审计**（#2028 + #1937）— 多跳 Agent 协作的追溯需求
2. **跨协议追踪**（#2026）— A2A↔MCP 调试链路
3. **信任信号标准化**（#1628, 96 评论）— 信任评估生态

ACP 当前差异化优势仍在：P2P 零服务器、轻量、skill_id routing 已领先 A2A v1.1。
