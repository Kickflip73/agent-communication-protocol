## Direct Message 模式 — v2.67 设计分析

### A2A v1.0.0 `SendMessage` 官方规范

来自 `specification/a2a.proto`：
```protobuf
message SendMessageResponse {
  oneof payload {
    Task task = 1;    // 复杂交互：创建 Task
    Message message = 2;  // 简单交互：直接返回 Message，不创建 Task
  }
}
```

来自 `docs/specification.md`：
> "The agent MAY create a new Task to process the provided message asynchronously **or MAY return a direct Message response for simple interactions**."
> "The operation MUST return immediately with either task information or response message."

### ACP v2.67 设计方案（基于官方 spec）

#### 端点变更

当前 ACP `POST /message:send` 始终返回 message 对象，不创建 Task。
v2.67 目标：**让 `POST /tasks` 也能返回 Message（不创建 Task）**，对齐 A2A SendMessage 语义。

更简洁的方案：**新增 `POST /message:send`** 作为 Direct Message 专用端点：

```
POST /message:send
Body: {
  "role": "user" | "agent",
  "parts": [...],              // A2A Part 格式
  "context_id"?: string,       // 可选，关联上下文
  "task_id"?: string           // 可选，关联已有 task
}

Response 200 (direct message):
{
  "ok": true,
  "type": "message",
  "message_id": "msg-<uuid>",
  "role": "agent",
  "parts": [{"type":"text","text":"..."}],
  "context_id"?: string,
  "timestamp": "2026-04-06T..."
}
```

#### 与 Task 流的对比

| 维度 | `POST /tasks` (Task 流) | `POST /message:send` (Direct Message) |
|------|------------------------|---------------------------------------|
| 适用场景 | 复杂、异步、需追踪 | 简单查询、ping、计算 |
| 返回结构 | `{task: {...}}` | `{message: {...}}` |
| 状态机 | submitted → working → completed | 无状态机，一次性 |
| 存储 | 持久化到 `_tasks[]` | 不存储（或可选短期缓存） |
| A2A 对齐 | `Task` payload | `Message` payload |

#### AgentCard 扩展
```json
{
  "capabilities": {
    "direct_message": true
  },
  "endpoints": {
    "message_send": "/message:send"
  }
}
```

#### 测试目标 DM-1..12
- DM-1: `POST /message:send` 返回 200 + `type:"message"` + `message_id`
- DM-2: role=user/agent 均接受
- DM-3: 不在 `GET /tasks` 中出现（不创建 Task）
- DM-4: `context_id` 传递正确
- DM-5: `task_id` 关联已有 Task（可选关联，不改变 Task 状态）
- DM-6: parts 支持 text/file/data 三种类型
- DM-7: 无 parts 时返回 400
- DM-8: 无 role 时返回 400
- DM-9: AgentCard `capabilities.direct_message = true`
- DM-10: AgentCard `endpoints.message_send` 指向正确路径
- DM-11: 并发 100 条 Direct Message — 全部 200，无状态污染
- DM-12: 无 `Content-Type: application/json` 时返回 415

## 结论与建议

1. **v2.66 `rejected` 状态**：与 A2A v1.0.0 规范完全对齐，无需修改。✅
2. **v2.67 Direct Message**：
   - A2A spec `SendMessageResponse` 的 `oneof {Task, Message}` 提供了明确的设计蓝图
   - 建议新增 `POST /message:send` 端点（而非修改 `/tasks`），保持向后兼容
   - `parts[]` 格式对齐 A2A `Part`（text/file/data）
   - 不创建 Task，不进状态机，纯一次性响应
3. **ACP 整体定位**：在信任基础设施（IR/WTRMRK/governance）方向已远超 A2A，保持领先。
