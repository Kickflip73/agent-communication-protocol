## 重点分析

### #1672 — Agent Identity Verification（新）

**提案方案**：中心化 CA（getagentid.dev）颁发 ECDSA P-256 证书，写入 AgentCard `verifiedIdentity.certificate` 字段，实时调用 `verificationEndpoint` API 验证。

**ACP 领先对比：**
- ACP 方案（v0.8+）：Ed25519 **自签名**（无 CA、无中心服务器）+ did:acp: DID 锚定
- A2A #1672 方案：需要中心注册商（getagentid.dev），实时验证 API
- **ACP 差异化优势**：P2P 离线可验证，无单点故障；v2.90 新增 `POST /identity/verify-card` 直接解决此需求

**P1 建议**：在 #1672 评论中提及 ACP 自签名方案作为无中心 CA 的替代路径。

### #1718 — Bilateral IR（更新）

**新进展（2026-04-08）**：
- aeoess 提出「adversarial fixture pack」格式：
  - 50+ 正常交互（多样对手方）
  - 20 个 inflated mutual interaction（可疑的相互虚增）
  - 5 个 colluding-pair inflation 场景
  - 自包含 JSON 对象：`scenario / agents / interactions / expected_trust_adjustment`
- MoltyCel 确认：colluding-pair inflation 在生产信任网络中已有实例

**ACP 现状**：`/ir/test-vectors` 端点已提供 deterministic bilateral IR test vectors（v2.64），但目前覆盖的是协议合规场景，**尚未覆盖 adversarial / collusion 场景**。

**差距识别**：ACP test vectors 缺少 adversarial fixture（伪造/通谋攻击用例）。

**P1 建议**：扩展 `/ir/test-vectors` 或新增 `/ir/adversarial-fixtures` 端点，提供 colluding-pair detection 测试用例 → 可在 #1718 发布并抢先 A2A。

### #1716 — Capability Token / wtrmrk_sequence_root（更新）

**新进展（2026-04-05）**：
- 64R3N 提出在 task metadata 中嵌入 `wtrmrk_sequence_root`（Merkle root over agent action sequences）
- 作为 `attestation_history_adjustment` 的底层原语
- 好处：无需 per-interaction 链上验证，只需验证 root

**ACP 现状**：
- ACP v2.61 已有 `sha256_chain_root`（bilateral IR Merkle chain root）
- ACP v2.57 capability token 有 `token_hash` 但没有 sequence-level Merkle commitment

**差距识别**：task-level `sequence_root` 字段尚未在 ACP capability token 中实现。

**P2 建议**：评估是否在 capability token 或 interaction record 中添加 `action_sequence_root` 字段（Merkle root over ordered action list）。
