## 14:10–14:29 Stark 先生直接对话 — 架构澄清 + 文档重写 + v1.4 战略决策

### 两个架构问题（Stark 先生提问，贾维斯解答）

**Q1：到底是 WebSocket 还是 SSE？**
- WebSocket (`:7801`) = Agent 间数据通道，双向全双工
- SSE (`/stream`) = Agent 给自己宿主程序的本地通知接口
- 两者不是替代关系，职责完全不同

**Q2：中继不是 P2P 失败后的降级措施吗？**
- 标准 P2P 打洞（WebRTC ICE）确实是「尝试直连→失败→Relay 降级」
- 当前 ACP 的 Relay = 永久中转路由节点，不是降级方案
- 设计原因：Agent 通信不是实时音视频，NAT 穿透复杂度不值得

## 17:11 緊急修復 — Docker CI 三個連鎖 Bug

### 問題來源
收到 GitHub Actions 郵件通知：Docker Publish workflow 失敗

### 根因鏈（三層嵌套 bug）

**Bug 1: `pip install` 空參數報錯**
- 症狀：`build-and-push (base)` job 19 秒失敗
- 原因：`$([ "$EXTRAS" = "full" ] && echo "..." || echo "")` 在 base 變體傳空字符串給 pip，`pip install` 報 "must give at least one requirement"
- 修復：改用 `if/fi` 分支，base 完全跳過 pip（commit 7327f1e）

**Bug 2: Docker 鏡像名含大寫字母**
- 症狀：`smoke test` job 失敗，"repository name must be lowercase"
- 原因：`${{ github.repository }}` 返回 `Kickflip73/...`（大 K），Docker 要求全小寫
- 修復：IMAGE_NAME 改為靜態小寫字符串 `kickflip73/...`（commit fa9a0b9）

**Bug 3: HTTP server 綁定 127.0.0.1，Docker 端口映射失效**
- 症狀：smoke test curl 15 秒無響應（exit code 56 / 7）
- 原因：`ThreadingHTTPServer(("127.0.0.1", port))` 只監聽 loopback，Docker `-p 8100:8100` 映射需要 `0.0.0.0` 才能從宿主機訪問
- 副因：base 鏡像缺少 websockets，容器啟動即退出（commit cb59790 先修）
- 修復：添加 `--http-host` CLI 參數（默認 127.0.0.1 向後兼容），Dockerfile CMD 加 `--http-host 0.0.0.0`（commit ea672a4）

### 最終結果
- Build & Push (base): ✅ 57s
- Build & Push (full): ✅ 1m24s  
- Smoke test: ✅ PASS
- GHCR 鏡像已成功發布：ghcr.io/kickflip73/agent-communication-protocol/acp-relay:latest

### 教訓
- Docker HTTP server 在容器內必須綁 0.0.0.0，否則端口映射無效（經典坑）
- CI workflow 中 `${{ github.repository }}` 含大寫，要用靜態小寫或 `toLower()` 轉換
- websockets 是 acp_relay.py 的硬依賴（不是可選），應在所有鏡像變體中安裝
