## 09:09 — ACP 测试轮（WS2/WS3 根因修复 + 5/5 全通过）

**Commit**: `e60c6fa`

### 根本原因（调查过程）
- `conftest.py` 的 `bypass_http_proxy` fixture（`scope=session`）在 pytest 启动时从 `os.environ` 删除所有代理变量
- `test_ws_stream.py` 用 `os.environ.copy()` 启动子进程 → 子进程无代理 → 无法访问 Cloudflare relay → `session_id`/`link` 永远 None → WS2/WS3 skip
- 手工运行正常（代理完好），pytest 运行异常（代理被删）

### 修复方案
1. `_GATEWAY_PROXY_ENV`: 模块加载时扫描 `/proc/*/environ`，从 gateway 进程还原代理变量
2. `_relay_env()`: 合并 `os.environ + _GATEWAY_PROXY_ENV`，确保 relay 子进程有代理
3. WS2/WS3 listener: 循环 recv() 跳过 `acp.peer` 事件，等待 `acp.message`

### 测试结果
- **WS1~WS5: 5/5 PASS（6.12s）**
- 快速回归（ws_stream + E + H + tasks_list）: **17/17 PASS（31.47s）**

### 知识沉淀
- `conftest.py proxy bypass` 是全套测试的基础设施，影响所有需要公网连接的子进程
- 需要公网的测试要么用 `_relay_env()` 模式，要么 `@pytest.mark.p2p` skip
- ws/stream 同时广播 `acp.peer` 和 `acp.message`，测试需要过滤事件类型
