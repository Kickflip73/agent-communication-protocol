## 二、链路第一步：巡检周期管理（Supply）

### 2.1 周期数据模型

```
PeriodDO:
  - periodCode: "2-2026-005"  (类型-年份-序号)
  - periodType: STORE_MANAGER(1) | QUALITY_CONTROL(2) | PHF_MACHINE_INSPECTION(3)
  - periodStart / periodEnd: 时间范围
  - previousPeriodId: 链式结构，指向上一个周期
  - status: NOT_STARTED(1) | IN_PROGRESS(2) | FINISHED(3) | SKIPPED(4) | ABANDONED(5)
```

### 2.2 3 种周期类型

| 类型 | 长度 | Lion Key | 说明 |
|------|------|---------|------|
| **店长巡检** | 2 周 | `store_manager_inspection_period_week` | 可跳过节假日 |
| **品控巡检** | 2 月 | `quality_control_inspection_period_month` | 结束对齐下月第一个周一 |
| **拼好饭设备巡检** | 1 天 | 固定 | 每日 |

### 2.3 周期切换完整流程（PeriodProcessorImpl.switchPeriod）

```
每天 00:00 Crane Job (PeriodSwitchJob) 触发：

1. 查询每个类型的最新周期
2. 判断最新周期是否已结束（now >= periodEnd）
   → 未结束: 直接返回
   → 已结束:
      a. 当前状态为 IN_PROGRESS → 变更为 FINISHED
      b. 创建新周期 buildNewPeriod():
         - 店长: nextStart + Lion配置的周数
         - 品控: nextStart + Lion配置的月数, 对齐到当月第一个周一
         - 拼好饭: nextStart + 1天
         - 店长需检查节假日，含则标记 SKIPPED
         - 设置 previousPeriodId 形成链式结构
      c. 品控周期切换 → 触发模板切换(inspectionConfigWriteAbility.changeTemplateState())
      d. 初始化新周期上下文(initializePeriodContext)
```

### 2.4 周期上下文（InspectionPeriodContextDO）

每个周期维护一个上下文，包含：
- **usingTemplateMap**: `{templateType -> templateId}` — 当前使用的巡检模板
- **subjectListMap**: `{subjectType -> SubjectListData}` — 巡检主体列表
  - `initial` / `current` / `final` 三组，对应初始/当前/最终巡检对象
  - subjectType: POI(门店) | KITCHEN(厨房)
- **scoreStatusMap**: `{scoreType -> scoreStatus}` — 出分状态
  - NOT_RELEASED / OFFICIAL_RELEASE / etc.

### 2.5 关键查询方法

| 方法 | 说明 |
|------|------|
| `getCurrentPeriod(periodType)` | 根据当前时间定位活跃周期 |
| `getPreviousPeriod(periodType)` | 通过 previousPeriodId 回溯 |
| `getLatestPeriod(periodType)` | 按 year+seq 排序取最新 |
| `querySMPeriodsByQCPeriodCode(qcCode)` | 品控周期内包含哪些店长周期 |

### 2.6 新周期开关（灰度）

```java
Lion: inspection_new_period_switch = false  // 默认关闭
```

## 三、链路第二步：巡检任务创建与执行（Kitchen Security）

### 3.1 巡检任务创建（InspectionJob）

```
InspectionJob (Crane Job, 每天定时触发):
  1. waitForPeriodSwitch(now) — 如果是 00:00 等待 2s 确保周期切换先完成
  2. 查询当前使用的巡检模板列表
  3. buildTriggerContext():
     - 查询厨房→巡检人映射 (kitchenPhysicalPoiId → List<InspectionInspector>)
     - 查询厨房→门店映射 (kitchenPhysicalPoiId → List<wmPoiId>)
     - 查询当前店长周期 + 品控周期
  4. 按模板类型分发任务：
     - 品控巡检(KITCHEN_INSPECTION/MERCHANT_INSPECTION) → 品控巡检任务
     - 店长巡检 → 店长巡检任务
     - 拼好饭设备巡检 → 设备巡检任务
```

### 3.2 巡检任务状态流转

```
InspectionTaskDO:
  - inspectionStatus: PENDING → IN_PROGRESS → COMPLETED / UNCOMPLETED
  - appealStatus: APPEALABLE → APPEALING → APPEAL_EXPIRED / APPEAL_APPROVED / APPEAL_REJECTED
  
周期切换时的处理（PeriodWriteAbility.switchPeriodPreProcess）:
  - PENDING 任务 → UNCOMPLETED（未完成）
  - APPEALABLE 任务 → APPEAL_EXPIRED（逾期未申诉）
```

### 3.3 新周期上下文初始化（Kitchen Security）

```
PeriodWriteAbility.createNewPeriodContext(periodCode, periodType):
  1. 查询当前使用中的巡检模板列表 → 设置 usingTemplateMap
  2. 初始化主体列表 subjectListMap:
     - 拼好饭: 从 phfInspectionObjectQueryAbility 查询巡检对象 POI
     - 店长: 从 inspectionInspectorManager 查询需巡检厨房 → 过滤已开业门店
     - 品控: 同上（role=QUALITY_CONTROL）
     - 三种主体: initial = current, final = 空
  3. 初始化出分状态 scoreStatusMap:
     - 过滤 FoodSafetyScoreTypeEnum 中与当前周期类型相关的评分类型
     - 全部初始化为 NOT_RELEASED
```

### 3.4 巡检维度与分类

| 维度 | 角色 | 对象 | 分类 | 说明 |
|------|------|------|------|------|
| 厨房 | 店长 | 厨房 | 线下/AI/视频 | 门店自查厨房 |
| 厨房 | 品控 | 厨房 | 线下/AI/视频 | 专业团队检查厨房 |
| 商家 | 店长 | 门店 | 线下/AI/视频 | 门店自查 |
| 商家 | 品控 | 门店 | 线下/AI/视频 | 专业团队检查门店 |
| 拼好饭 | 系统 | 门店 | AI | 设备自动巡检 |

### 4.2 评分计算模板方法模式（ScoreCalculateTemplate）

```
ScoreCalculateTemplate.calculate(scoreTypeEnum, periodCode, subjectIdList):
  
  1. buildContext(): 从枚举自动推导所有参数
     - PeriodType → Role → Subject → Template → ItemClassification
     - 查询算分周期（指定 periodCode 或上个周期）
     - 查询周期上下文中的巡检对象列表
     - 归档最终主体列表
  
  2. 分批处理（默认 100 条/批）:
     对每个 subjectId 调用 doCalculateAndRecordResult(subjectId, context)
     → 子类各自实现具体算分逻辑
  
  3. batchUpsertScore() — UPSERT 保证幂等
  
  4. customPersist() — 子类可重写个性化持久化
  
  5. 变更周期上下文出分状态为 OFFICIAL_RELEASE
```

### 4.3 评分计算子类（具体实现）

| 子类 | 评分类型 | 计算逻辑 |
|------|---------|---------|
| KitchenAvgPoiScoreCalculateProcessor | kitchen_avg_* | 厨房维度平均分（取厨房下所有门店分数的均值） |
| ...其他子类 | 各具体评分 | doCalculateAndRecordResult() 各自实现 |

### 4.4 算分前提条件

- 上个周期必须已结束
- 新周期必须有完整的巡检对象数据
- 批量 UPSERT 保证幂等性
- 满分处理：子类必须实现 `dealFullScoreInfo()`

## 六、链路第五步：激励金体系（Supply）

### 6.1 激励金核心数据模型

**IncentivePoiMetricDO（门店月度指标）:**
```
- wmPoiId: 门店ID
- yearMonthCode: "2026-05"（格式）
- metric: 指标编码（TECH_SERVICE_FEE_MONEY / ORDER_ACTUAL_PAY_MONEY / RENTAL_ACTUAL_PAY_MONEY / BUSINESS_SCORE_AB_GRADE_COUNT）
- value: 指标值（分）
```

**IncentivePoiMonthlyRecordDO（门店月度激励记录）:**
```
- recordStatus: 1-进行中, 2-归档中, 3-已归档
- incentiveStatus: 1-核算中, 2-未获得, 3-获得, 4-获得且已达上限
- taskRuleGroupList: 任务条件组快照（JSON）
- metricProgressList: 指标进度快照（JSON）
- originIncentiveAmount: 原始激励金额（分）
- finalIncentiveAmount: 最终激励金额（分）
```

**IncentivePaymentRecordDO（打款记录）:**
```
- status: 1-待打款, 2-取消打款, 3-打款成功, 4-打款失败
- originPaymentAmount: 计划金额
- finalPaymentAmount: 最终金额
- actualPaymentAmount: 实际金额
```

### 6.2 激励金计算公式

```
预估金额 = MIN(基数金额 × 系数, 房租账单实付金额)

其中：
  基数金额 = 本月 TECH_SERVICE_FEE_MONEY（技术服务费，单位分）
  系数 = 依据 ORDER_ACTUAL_PAY_MONEY（订单实付金额）分层：
    ≥ 8,000,000 分 → 100%
    ≥ 6,000,000 分 → 80%
    ≥ 4,000,000 分 → 50%
    < 4,000,000 分 → 0%
  房租账单实付金额 = RENTAL_ACTUAL_PAY_MONEY（若无数据默认 1,000,000 分上限）
```

### 6.3 激励金资格规则引擎

```
IncentiveTaskRuleGroupConfigDO:
  - ruleGroupTitle: 规则组标题
  - rules: List<IncentiveTaskRuleConfigDO>
    - metricCode: 指标名称
    - operator: 操作符（> / < / =）
    - targetValue: 阈值
    - description: 规则描述
  
规则逻辑：
  - 规则组之间：AND 连接（所有组必须达标）
  - 组内规则之间：OR 连接（组内任意一条达标即可）
```

### 6.6 激励金计算流程

```
IncentivePoiMetricSyncJob (每天 09:00):
  1. 同步各指标数据到 incentive_poi_metric:
     - BusinessScoreMetricSyncProcessor: 经营分
     - OrderActualPayMetricSyncProcessor: 订单实付金额
     - RentalActualPayMetricSyncProcessor: 房租
     - TechServiceFeeMetricSyncProcessor: 技术服务费
  
  2. 计算进度:
     - IncentiveCalculationAbility.calculateQualificationStatus()
       → 解析规则组 → 与指标数据对比 → 返回进度状态
     - isOverallQualified() → AND 连接判断
  
  3. 计算预估金额:
     - IncentiveCalculationAbility.calculateEstimatedAmount()
       → 基数 × 系数 vs 房租上限
  
  4. 更新 monthly record:
     - 更新 taskRuleGroupList 快照
     - 更新 metricProgressList 快照
     - 更新 incentiveStatus
```

### 7.1 权益接口

```
ServiceRightsThriftServiceImpl.getServiceRights():
```
