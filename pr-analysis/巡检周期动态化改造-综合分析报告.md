### 2.3 核心流程：周期切换（switchPeriod）

```
switchPeriod(latestPeriod, now):
  1. 如果当前周期未结束 → 直接返回
  2. 如果当前周期状态是 IN_PROGRESS → 变更为 FINISHED
  3. 创建新周期 buildNewPeriod(lastPeriod):
     - 店长巡检: 加上 Lion 配置的周数
     - 品控巡检: 加上 Lion 配置的月数，对齐到下月第一个周一
     - 拼好饭: 加 1 天
     - 店长巡检需检查节假日，含则标记为 SKIPPED
  4. 品控周期切换时 → 触发模板切换(inspectionConfigWriteAbility.changeTemplateState())
  5. 初始化周期上下文(inspectionPeriodContextProcessor.initializePeriodContext())
```

## 三、评分体系（Kitchen Security 仓库）

### 3.1 评分计算模板模式（ScoreCalculateTemplate）

采用**模板方法模式**，定义了评分计算的标准流程：

```
calculate(scoreTypeEnum, periodCode, subjectIdList):
  1. buildContext(): 从枚举自动推导所有参数
     - PeriodType → Role → Subject → Template → ItemClassification
     - 查询算分周期（指定或上个周期）
     - 查询周期上下文中的巡检对象列表
     - 归档最终主体列表
  2. 分批处理（默认100条/批）:
     - doCalculateAndRecordResult(subjectId, context)  // 子类实现具体算分逻辑
  3. batchUpsertScore()  // UPSERT 保证幂等
  4. customPersist()     // 子类可重写，个性化持久化
  5. 变更周期上下文出分状态为 OFFICIAL_RELEASE
```

### 3.3 评分计算关键规则

- **算分前提**：上个周期已结束且产生新周期的数据
- **批量 UPSERT**：保证幂等性，重复计算不会产生重复数据
- **满分处理**：子类必须实现 `dealFullScoreInfo()`
- **周期上下文**：每个周期维护一个 `InspectionPeriodContextDO`，包含巡检对象列表和出分状态

## 六、风险点与建议关注

### 6.1 高风险点

| 风险 | 说明 | 建议 |
|------|------|------|
| **R1: 周期数据一致性** | 周期链式结构（previousPeriodId）断裂会导致查询异常 | 确保切换时 previousPeriodId 正确设置 |
| **R2: 节假日跳过逻辑** | 店长巡检含节假日则标记 SKIPPED，可能导致部分门店无有效周期 | 关注 SKIPPED 状态的后续处理 |
| **R3: 品控周期对齐** | 品控周期结束时间对齐到下月第一个周一，可能跨月 | 验证跨月时的 periodYear 和 periodSeq 计算 |
| **R4: 新周期开关** | 默认关闭，上线需确认 Lion 配置已正确设置 | 上线前验证开关值和周期配置 |
| **R5: 评分幂等性** | batchUpsertScore 依赖数据库唯一键，需确认约束 | 验证 score DO 的索引/唯一约束 |

### 6.2 建议关注

1. **激励金结算与周期的联动**：激励金 Job 是否正确读取了最新的周期配置？
2. **L4 标签计算时机**：标签 Crane 是否在周期结束后、评分发布后才执行？
3. **前端展示兼容**：新的 periodCode 格式（type-year-seq）前端是否正确解析和展示？
4. **数据迁移**：历史周期数据是否需要迁移或补录？
5. **监控告警**：周期切换失败的告警是否配置？
